# Milestone v1.1: Onboarding Tour

**Status:** SHIPPED 2026-04-12
**Phases:** 6-8
**Total Plans:** 10

## Overview

Guide new users through SetCash's core features with a 6-step speech-bubble tooltip tour on first login (always for test/demo users).

## Phases

### Phase 6: Tour Infrastructure
**Goal**: The tour has a persistent backend, a React context for state management, and a single configuration file defining all 6 steps with their target selectors and content
**Depends on**: Phase 5 (previous milestone)
**Requirements**: INFRA-01, INFRA-02, INFRA-03, INFRA-04
**Plans**: 4 plans

Plans:
- [x] 06-01: Add hasSeenTour to User model and wire through JWT/session pipeline
- [x] 06-02: Create centralized tour step configuration (6 steps)
- [x] 06-03: POST /api/tour/complete endpoint with rate limiting and client wrapper
- [x] 06-04: TourProvider React context and protected layout mount

### Phase 7: Tour UI Components
**Goal**: Users see a polished, accessible speech-bubble tooltip tour with spotlight highlighting and full navigation controls
**Depends on**: Phase 6
**Requirements**: UI-01, UI-02, UI-03, UI-04
**Plans**: 3 plans

Plans:
- [x] 07-01: TourOverlay — SVG mask spotlight overlay with cutout
- [x] 07-02: TourTooltip — Speech-bubble tooltip with arrow and navigation controls
- [x] 07-03: TourController — Orchestrator with positioning, keyboard, and barrel export

### Phase 8: App Integration
**Goal**: The tour is wired into the live application, starts automatically for the right users, works on all viewports, and respects the current theme
**Depends on**: Phase 7
**Requirements**: INTG-01, INTG-02, INTG-03, INTG-04
**Plans**: 3 plans

Plans:
- [x] 08-01: Attach data-tour attributes to 6 target host components
- [x] 08-02: Tour runtime adaptation (auto-start gating, viewport-aware targets, retry+skip-forward)
- [x] 08-03: Requirements correction (INTG-03 breakpoint) and theme verification checklist

## Milestone Summary

**Key Decisions:**
- Lightweight tooltip tour, not interactive walkthrough (minimal complexity)
- Per-user tour state flag (boolean, demo users bypass)
- 6 fixed steps covering core workflow
- CSS variable-only approach for theme support (Tailwind v4 `dark:` doesn't respond to `[data-theme="dark"]`)
- `desktopOnly` step flag for project-switcher (only element hidden on mobile)
- Retry-3x-then-silent-skip for missing targets with abort-without-complete semantics

**Issues Resolved:**
- TourController never mounted in protected layout (discovered during verification)
- Dead `dark:` Tailwind classes replaced with CSS variable approach
- Missing hasSeenTour DB migration added
- INTG-03 breakpoint corrected from 768px to 1024px (matching Tailwind `lg:`)

**Issues Deferred:**
- Pre-existing TypeScript errors in test/e2e files (unrelated to tour)
- ESLint cannot run from non-TTY agent shell (no `.eslintrc` file)

**Technical Debt Incurred:**
- None significant
